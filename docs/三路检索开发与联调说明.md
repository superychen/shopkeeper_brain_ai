# 三路检索开发与联调说明

## 入口与阅读顺序

完整图入口为 `knowledge/processor/query_processor/retrieval_graph.py`。
原 `main_graph.py` 的 `run_item_name_confirm` 保持只确认商品的行为。

```python
import asyncio
from knowledge.processor.query_processor.retrieval_graph import arun_query_retrieval

async def main():
    result = await arun_query_retrieval({"original_query": "RS-12 怎么测直流电压？"})
    print(result["item_confirm_status"], result["retrieval_status"])
    print(result["embedding_chunks"])
    print(result["hyde_embedding_chunks"])
    print(result["web_search_docs"])

if __name__ == "__main__":
    asyncio.run(main())  # 已有异步 HTTP 入口直接 await，不再调用 asyncio.run。
```

在项目根目录使用 `knowledge/.venv/Scripts/python.exe` 执行脚本。常驻服务可复用
`build_retrieval_graph()` 返回的图并调用 `ainvoke`，避免每次重建 profile 缓存。
图内部会先执行商品确认，外部传入 confirmed 字段不能跳过确认。

按以下顺序阅读代码中的编号：

1. `retrieval_graph.py`：清空旧结果，执行商品确认，决定是否放行。
2. `prepare`：校验问题和标准商品列表，不访问模型或数据库。
3. `retrieval_base.py`：管理本路超时、商品并发和局部失败，返回独占字段。
4. `vector_search_node.py` / `retrieval_embedding_service.py`：编码问题并复用入库 profile。
5. `chunk_search_repository.py`：两条 ANN 使用相同参数化商品/profile 条件，COSINE/IP 等权融合。
6. `hyde_search_node.py` / `hyde_generation_service.py`：生成假设后查真实切片，失败不复制向量路。
7. `web_mcp_search_node.py` / `bailian_search_service.py`：初始化会话、发现工具、检查参数、调用和解析网页。
8. `join`：等待三路结束，汇总状态；本期不生成最终答案。

## 配置和运行行为

配置变量已补入 `knowledge/.env.example`，实际凭据通过环境或本机 `.env` 注入；示例不含密钥。
正文默认每商品每路 5 条，每个 ANN 先取 50 条，权重 0.5/0.5。
商品确认 0.7 保持原行为，正文低于 0.7 的切片仍可进入后续重排。

网络未配置返回 `mcp_configuration_missing`，本地两路仍可工作；显式设置
`QUERY_WEB_ENABLED=false` 则网络 skipped，不造成整体 partial。
HyDE 开关为 `QUERY_HYDE_ENABLED`。

超时默认向量20秒、HyDE45秒、网络25秒；单次工具10秒、生成15秒，可通过 RetrievalConfig 构造参数覆盖。
同路最多两商品并发，编码执行器1个、Milvus执行器4个；跨请求最多4个 HyDE 外呼和4个 MCP 会话。
编码执行器满时最多等待5秒，再返回 retrieval_busy，避免线程池无限堆积。
这些上限针对新检索模块，导入/旧确认模型调用仍遵循各自已有执行方式；生产高并发应隔离导入与查询工作进程。

`success` 表示完成且有候选，`empty` 表示正常完成但无候选，`partial` 表示有部分故障，
`failed` 表示全部启用分支失败，`skipped` 表示未放行或禁用。
商品级诊断位于 `vector_search_meta`、`hyde_search_meta`、`web_search_meta` 的 items 字段。

例如网络超时、两路本地有候选：三份列表仍保留本地证据，汇总 partial；不能解释成“网上没有资料”。
HyDE 的假设文本只在调用局部存在，不返回给用户、不入库、不成为证据。

## 百炼联调前置条件

需要目标 EnhancedSearch 服务“外部调用”的实际 URL 和工具名。客户端使用 MCP 2.1.1 的
`streamable_http_client`，按照该版本二元返回流建立 ClientSession。
当前只接受百炼 `dashscope.aliyuncs.com/api/v1/mcps/` 下 HTTPS 地址，不接受任意用户 URL。

每会话调用 tools/list，并用返回 inputSchema 校验 query/count；遇到未知必填参数明确失败。
当前响应适配器支持 structuredContent 或多个文本 JSON 块中的 `pages` 列表，字段 title/url/snippet。
该适配器已经过离线契约测试，**EnhancedSearch 实际返回格式尚未验证**；如实际字段不同，应按脱敏样本增加明确适配，不能把错误结构当空结果。

未对用户提供的密钥进行持久化。本次未产生真实百炼搜索调用，也未声称联网已验收。
尚未实现自动重试、RRF、rerank、网页全文抓取、查询 HTTP API 或最终答案节点。
